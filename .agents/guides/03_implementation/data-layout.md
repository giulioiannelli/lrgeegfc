# Data Layout & `lrg-eegfc data normalize`

Canonical specification of how raw sEEG patient data is organized on disk,
what the layout rules are, which tools enforce them, and which per-patient
quirks every agent must keep in mind.

**START HERE** when touching anything under `data/raw/stereoeeg_patients/`.

---

## 1. Canonical patient layout

Every patient directory under `data/raw/stereoeeg_patients/` has **exactly
this shape**. No exceptions — the loaders depend on it byte-for-byte.

```
data/raw/stereoeeg_patients/Pat_NN/
├── resting/
│   ├── rest_pre.mat                # canonical phase name
│   ├── rest_post.mat
│   ├── rest_pre.info.txt           # optional: vendor per-phase metadata
│   └── rest_post.info.txt          #   (sampling rate, bandpass cutoffs)
├── task/                           # optional: absent only if patient lacks task phases
│   ├── task_learn.mat
│   ├── task_test.mat
│   ├── task_learn.info.txt         # optional
│   └── task_test.info.txt          # optional
├── implant/
│   └── implant_pat_NN.xlsx         # single source of truth for epileptic labels
│                                   # (red-font cells) and electrode coordinates
├── channel_labels.csv              # single labels file — header `label`, CSV-quoted,
│                                   # e.g. `"A 1,G2"`. No .txt or .mat duplicates allowed.
├── implant_pat_NN.csv              # generated from xlsx: label,x,y,z,anatomy columns.
│                                   # Regenerated by the normalizer; edit the xlsx, not this.
└── provenance.md                   # vendor→canonical mapping + sha256 of each source file
```

### Invariants

1. **Phase file names are `rest_pre | rest_post | task_learn | task_test`**. Nothing else. These map 1:1 onto the project's `PHASE_LABELS` constant.
2. **Phase files live under `resting/` or `task/`**, never at the patient root. The loader maps phase key → subdir via a trivial rule (`rest_* → resting/`, `task_* → task/`).
3. **Patient identifier is `pat_NN`** internally (lowercase, zero-padded two-digit). The on-disk directory name is still `Pat_NN` for historical consistency with external references; the loader tolerates both — see §5.
4. **The xlsx under `implant/` is the ground truth for epileptic contacts.** `load_epileptic_nodes()` reads cell font colors via openpyxl. Never convert it to another format.
5. **`implant_pat_NN.csv` is a derived artefact.** The normalizer rewrites it from the xlsx whenever the migration runs. Do not hand-edit.
6. **`channel_labels.csv` is the single label file.** `.txt`/`.mat` copies must not exist at the patient root or inside `resting/`/`task/`.
7. **`provenance.md`** records, per-patient, the vendor filename → canonical filename mapping for each `.mat` and the xlsx, plus the sha256 of each file at migration time. Always present.

## 2. `lrg-eegfc data normalize` — the normalizer

Single tool that enforces §1 on any patient directory. Handles fresh drops,
legacy vintages, and heterogeneous vendor filename conventions.

### Usage

```bash
# Dry-run (safe default): show planned actions for all patients, write nothing.
lrg-eegfc data normalize

# Dry-run for a subset.
lrg-eegfc data normalize --patients Pat_13 Pat_14

# Save the combined plan to disk.
lrg-eegfc data normalize --report .agents/reports/2026-04-22_migration-plan-dryrun.md

# Apply the plan — actually move/rename/generate/delete.
lrg-eegfc data normalize --apply

# Combined: apply only to Pat_15.
lrg-eegfc data normalize --patients Pat_15 --apply
```

### What it does

For each selected patient, the planner inspects the current state and emits
an ordered action list of kinds:

| action | meaning |
|--------|---------|
| `mkdir` | create a canonical subdir (`resting/`, `task/`, `implant/`) |
| `rename` | move+rename a vendor file to its canonical name |
| `generate_csv` | rebuild `implant_pat_NN.csv` from the xlsx |
| `generate_labels` | write `channel_labels.csv` from a vendor `.txt` |
| `verify_labels` | confirm two label sources refer to the same contact set |
| `delete` | remove a redundant duplicate (verified label txt/mat copies, stale symlinks, legacy CSVs) |
| `rmdir` | remove a now-empty vendor subdir (`0.53to300Hz_*`, `Implant_locations/`) |
| `write_provenance` | emit the per-patient `provenance.md` |
| `noop` | recorded skip (e.g. patient has no task phase) |

### Idempotency

The planner detects what's already canonical and only emits actions for
what remains. Re-running `--apply` is safe: a fully-migrated patient
produces a plan with only the provenance re-write.

### Label comparison tolerance

The `verify_labels` step uses **contact identity**, not byte equality.
Same-contact differences in the following are tolerated (files on disk
are **not** altered):
- reference suffix annotation — `A 1,G2` vs `A 1` (suffix omitted)
- whitespace — `A 1` vs `A1`
- Italian-prime encoding artefacts — `P' 12` vs `Pì 12` vs `P� 12`
  (per the canonical `parse_seeg_label()` normalizer at
  `src/lrg_eegfc/utils/io/patient.py`)

A contact-set mismatch is a hard error and aborts the apply.

## 3. Adding a new patient

1. Drop the vendor directory as `data/raw/stereoeeg_patients/Pat_NN/`.
   Any layout is accepted — see §4 for the patterns the normalizer knows.
2. `lrg-eegfc data normalize --patients Pat_NN`  ← preview only.
3. Inspect the plan. Unexpected warnings? Fix the vendor drop or widen
   the normalizer's candidate list in
   `src/lrg_eegfc/utils/io/patient_bootstrap.py`.
4. `lrg-eegfc data normalize --patients Pat_NN --apply`.
5. `lrg-eegfc data inspect --patients Pat_NN -v` — sanity-check the
   timeseries shape and sampling rate per phase.
6. Update `PATIENTS_4PHASE` in `src/lrg_eegfc/config/const.py` if the
   new patient has all 4 phases.
7. If the new patient's sampling rate differs from 2048 Hz, add an entry
   to `_FS_OVERRIDES` in `src/lrg_eegfc/workflow/fc.py`.
8. Update the roster tables in this file (§6) and in `CLAUDE.md`.

## 4. Vendor → canonical resolution rules

The normalizer searches for each canonical file in this order. The first
hit wins; a second duplicate triggers a warning. Defined in
`patient_bootstrap.py:PHASE_SOURCE_CANDIDATES` and `_locate_implant_xlsx`.

### Phase `.mat` files

| canonical target | vendor candidate paths (searched in order) |
|------------------|---------------------------------------------|
| `resting/rest_pre.mat` | `0.53to300Hz_resting/PRE_STIM_resting_Pre_Data.mat`<br>`0.53to300Hz_resting/PRE_STIM_restingPre_Data.mat`  *(Pat_10 anomaly: missing `_`)*<br>`Resting_PreTask_Data.mat` *(Pat_02 legacy-flat)*<br>`RestingPreTask_Data.mat` *(Pat_03 legacy-flat)* |
| `resting/rest_post.mat` | `0.53to300Hz_resting/PRE_STIM_resting_Post_Data.mat`<br>`0.53to300Hz_resting/PRE_STIM_restingPost_Data.mat`<br>`Resting_PostTask_Data.mat`<br>`RestingPostTask_Data.mat` |
| `task/task_learn.mat` | `0.53to300Hz_task/PRE_STIM_task_learning_Data.mat`<br>`Task_learning_Data_TimeSeries.mat` |
| `task/task_test.mat` | `0.53to300Hz_task/PRE_STIM_task_test_Data.mat`<br>`Task_test_Data_TimeSeries.mat` |

### Implant xlsx

Searched under these names, first hit wins (mixed-case + padded tolerated):

```
Pat_NN/Implant_pat_{N}.xlsx
Pat_NN/Implant_pat_{NN}.xlsx
Pat_NN/implant_pat_{N}.xlsx
Pat_NN/implant_pat_{NN}.xlsx
Pat_NN/Implant_locations/Implant_pat_{N}.xlsx
Pat_NN/Implant_locations/Implant_pat_{NN}.xlsx
Pat_NN/Implant_locations/implant_pat_{N}.xlsx
Pat_NN/Implant_locations/implant_pat_{NN}.xlsx
Pat_NN/implant/implant_pat_{NN}.xlsx
```

If none match and `Implant_locations/` contains exactly one `*.xlsx` with
a non-canonical stem (e.g. `implant_CM.xlsx` = patient initials), the
normalizer renames it and emits a warning. Multiple non-canonical xlsx →
hard error (ambiguous, manual intervention required).

### Channel labels

Sources (all `.txt` or `.csv` containing labels, searched in this order):

```
0.53to300Hz_task/channel_labels.txt
0.53to300Hz_resting/channel_labels.txt
0.53to300Hz_task/channel_labels.csv
0.53to300Hz_resting/channel_labels.csv
task/channel_labels.txt
resting/channel_labels.txt
task/channel_labels.csv
resting/channel_labels.csv
channel_labels.txt
```

If the canonical `channel_labels.csv` at the patient root already exists,
each duplicate is verified-and-deleted. Otherwise the first duplicate is
promoted to canonical and the rest verified-and-deleted.

### Per-phase INFO.txt

```
0.53to300Hz_resting/resting_Pre_INFO.txt   →  resting/rest_pre.info.txt
0.53to300Hz_resting/resting_Post_INFO.txt  →  resting/rest_post.info.txt
0.53to300Hz_task/task_learning_INFO.txt    →  task/task_learn.info.txt
0.53to300Hz_task/task_test_INFO.txt        →  task/task_test.info.txt
```

Preserved because they contain vendor-supplied recording metadata in
human-readable form.

## 5. What the loaders expect

| Loader | Looks for |
|--------|-----------|
| `load_mat_pat_data(patient, phase, root)` at `utils/io/loaders.py` | `root/patient/{subdir}/{phase}.mat` where `subdir = "resting"` if phase starts with `rest_`, else `"task"`. *(Post-refactor; see Stage D below.)* |
| `load_implant_locations()` / `load_patient_metadata()` at `utils/io/patient.py` | `root/patient/implant_pat_{NN}.csv` + `root/patient/channel_labels.csv` |
| `load_epileptic_nodes()` at `utils/io/patient.py:327` | `root/patient/implant/implant_pat_{NN}.xlsx` (tolerates legacy paths during transition) |
| `list_patients()` at `config/const.py:56` | Any directory under `data/raw/stereoeeg_patients/` whose name starts with `Pat_` |

### Epileptic-zone annotations (red-font cells in the xlsx)

## 7. Provenance file format

Each patient carries `provenance.md`:

```markdown
# Provenance — Pat_NN

- Import date: YYYY-MM-DD
- Canonical id: `pat_NN`

## Source → canonical mapping

| canonical | vendor filename | sha256 |
|-----------|-----------------|--------|
| `resting/rest_pre.mat`            | <vendor path>       | <hex> |
| `resting/rest_post.mat`           | <vendor path>       | <hex> |
| `task/task_learn.mat`             | <vendor path>       | <hex> |
| `task/task_test.mat`              | <vendor path>       | <hex> |
| `implant/implant_pat_NN.xlsx`     | <vendor path>       | <hex> |

## Notes
...
```

Auto-regenerated every time `data normalize --apply` runs. Preserves
vendor-filename history across re-runs by parsing the previous
`provenance.md` and re-injecting known mappings.
